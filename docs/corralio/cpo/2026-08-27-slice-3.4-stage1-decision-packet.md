# Slice 3.4 (Schedule Connection Activation) — Stage 1 CPO Decision Packet
**2026-08-27 · Chief Product Officer · Response to Section 6 of `docs/prompts/corralio-slice-3.4-schedule-connection-activation.md`**

This is the formal, written resolution of Section 6's six-item CPO Decision Gate, filed the same way Slice 4.6's Section 68 decisions were (`docs/corralio/cpo/`), before any Stage 2 implementation may begin. Codex may proceed with the Section 1 audit and the Stage 1 design work this packet informs, but must not begin Stage 2 implementation until this packet is read alongside the prompt.

## Decisions

1. **Launch platform set.** Confirmed as **GameChanger, TeamSnap, Stack Team App**, plus the universal "Other calendar" `MANUAL` fallback. This replaces the prompt's original provisional candidate set (GameChanger, TeamSnap, SportsEngine/MySE), which was built from TI-borrowed evidence alone in the absence of any Corralio-side usage data.

   **Platform naming correction (2026-08-27, verified via web search, not assumed):** the third platform is named **Stack Team App**, not "SportsConnect/Blue Sombrero" as an earlier draft of this decision had it. Blue Sombrero no longer exists as a standalone product — Blue Sombrero, Affinity Sports, and Stack Sports merged years ago into **Sports Connect**, the backend club/league-management platform (itself now marketed as "Sports Connect: A PlayMetrics Company" following a June 2025 Stack Sports / PlayMetrics merger under Genstar Capital). Sports Connect's real parent-facing companion app is either **Stack Team App** or **GameChanger Team Manager**, depending on which the club/league selects — confirmed directly from public product evidence. A retained test schedule also uses Stack Team App. **Showing "Blue Sombrero" as an in-product platform choice would have shown parents a defunct brand name — this correction is a real product-quality catch, not cosmetic.**

   **Evidentiary basis, corrected 2026-08-27 — the first draft inaccurately stated all three platforms were already linked and pulling live events into Corralio.** GameChanger and TeamSnap were connected first. **Stack Team App was not connected to Corralio yet** at that point, although representative events existed in that third-party platform.

   **Further updated 2026-08-27 (same day, later): Stack Team App was connected into Corralio**, alongside GameChanger and TeamSnap. All three launch-set platforms are therefore represented in retained test data, not just directionally justified. This still does not change the underlying thinness of the evidence: **one test household and no independent pilot families onboarded yet.** Treat this as the correct starting set for V1, not as validated proof that these three are what a representative sports family uses. Revisit once real pilot families are onboarded (Section I of the execution plan's pre-launch test is the natural point to gather this). But decision 2's bounded audit can now read ingestion evidence for all three platforms rather than two — see the corresponding update there.

   **SportsEngine/MySE is dropped from the V1 launch set**, despite having real, tested precedent in TI's own UAT log (`docs/qa/ti-planner-ics-uat.md`) — that evidence was never backed by actual Corralio usage, and the prompt's own instruction is to prioritize platforms relevant to current/pilot families, not to support every platform with any evidence at all. It may be added back once real pilot data justifies it.

2. **Bounded real-feed verification pass: deferred to Stage 2.** Stage 1 remains pure audit/design with no new external provider calls. **However — and this is a free upgrade to Stage 1's evidence, not a new verification pass —** Stage 1's audit (Section 1 of the prompt) must additionally read the existing test household's `corralio_schedule_sources` and `corralio_events` rows and report only aggregate ingestion behavior: event coverage, parsing anomalies, cancellation/update handling, and anything resembling TeamSnap's known `00:00` time-default edge case from TI's UAT. **Corrected 2026-08-27, then updated again the same day:** this check initially would only have found data for GameChanger and TeamSnap, since Stack Team App was not yet connected. **With Stack Team App now connected, this audit step should find Corralio-side ingestion data for all three launch platforms.** This costs zero new provider calls — it is reading data that already exists — and is materially stronger evidence than a synthetic test-feed check would be.

   **Compatibility-tier implication, updated:** GameChanger and TeamSnap may be assigned `COMPATIBLE` in Stage 1 design, inheriting TI's partial real-feed precedent as supporting evidence per the prompt's Section 3 semantics, now further supported by Corralio-side ingestion history once Stage 1's audit reads it. **Stack Team App (Sports Connect) still has no real-feed testing evidence from TI's UAT** (TI's own log lists this platform under its legacy "Sports Connect/Blue Sombrero" naming as explicitly "not yet tested" — read that as referring to today's Stack Team App / Sports Connect, not a defunct separate Blue Sombrero product) — **but the retained Stack Team App test connection lets Stage 1 report first-party Corralio ingestion evidence for it, which is stronger than TI's borrowed precedent.** If that audit comes back clean (events importing correctly, no parsing anomalies), Stack Team App can reasonably move to a test-evidence-backed provisional `COMPATIBLE` rather than `MANUAL`; if the audit finds problems or the read comes back empty, it should stay `MANUAL` or an honestly labeled provisional tier until fixed. Codex's Section 1 audit report should state plainly which of these two outcomes it found — do not assume the compatible tier without checking.

3. **Structured source-of-truth format: typed code module**, not a database table. Simpler for a small, slow-changing launch platform list; versioned via ordinary code review; avoids a migration for V1. Maintained going forward as part of ordinary engineering changes to this module — no separate content-ops workflow implied by this decision.

4. **Slice 4.4B provider/source classifier: kept separate.** This slice implements a narrower, activation-only platform tag rather than building 4.4B's shared classifier now. 4.4B's classifier exists to support a harder, security/trust-relevant venue-creation decision; this slice only needs to recognize what a parent typed or picked. Building the shared version now risks scope creep and delay on an activation-focused slice. The overlap is noted for a future slice to reconcile if and when it becomes worth doing, not solved here.

5. **Microcopy — approved as drafted:**
   - Entry point: **"Where does this schedule live?"** with platform tiles for GameChanger, TeamSnap, Stack Team App, and "Other calendar."
   - Invalid/private URL failure: reuse TI's exact proven copy — *"This looks like a private or local address, not a public calendar link."*
   - Non-ICS failure: reuse TI's exact proven copy — *"This link doesn't appear to be an iCal/ICS calendar."*
   - Success: **"Schedule connected — we found [N] upcoming events"** followed immediately by a **"Connect another schedule"** call to action.

6. **Analytics event names — approved as drafted**, matching the existing `corralio_usage_*`/RPC naming convention from Slice 4.2A:
   `corralio_connect_platform_selected`, `corralio_connect_instructions_viewed`, `corralio_connect_link_submitted`, `corralio_connect_feed_validated`, `corralio_connect_events_imported`, `corralio_connect_second_schedule_attempted`, `corralio_connect_weekend_viewed`.
